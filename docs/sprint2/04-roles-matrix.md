# S2-04. Матрица прав по ролям

Статус: **реализовано и покрыто тестами** (`RoleMatrixIntegrationTest`, `FlockIntegrationTest.operatorWorksOnlyWithAssignedHouses`). Изменения матрицы согласует PO.

Права проверяются на backend в два слоя:

1. **URL и метод** — `SecurityConfig`. Чтение (`GET`) доступно всем ролям, ниже — кто может менять.
2. **Данные** — `AccessService`: оператор видит и правит только птичники, на которые его назначили (S2-05). Остальные роли работают со всеми птичниками площадки.

Защитные правила:

- Администратор не может снять с себя роль или заблокировать себя; в системе всегда остаётся хотя бы один активный администратор.
- Заблокированный пользователь не входит; выданный ранее токен живёт до истечения срока (`AUTH_JWT_TTL`, по умолчанию 12 ч).
- Должность (`users.role`) — только подпись в интерфейсе, права задаёт `access_role`.
