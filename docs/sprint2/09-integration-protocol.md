# S2-09. Протокол интеграции датчиков и учётных систем

Статус: **реализовано** (issue #27). HTTP-приём работает с Модуля 1 (S1); MQTT-шлюз (S4-06) и импорт учёта (S4-07) — со спринта 4, см. [docs/sprint4](../sprint4/README.md).

## 1. Телеметрия по HTTP (работает)

`POST /api/v1/telemetry/readings`, заголовок `X-Api-Key: <TELEMETRY_INGEST_API_KEY>`, тело — пачка показаний одного шлюза:

```json
{
  "gatewayId": "GW-FARM-1-HOUSE-4",
  "readings": [
    {"sensorCode": "TEMP-HOUSE-4-01", "type": "TEMPERATURE", "value": 26.4, "unit": "C", "measuredAt": "2026-10-20T08:15:00Z"}
  ]
}
```

| Правило | Значение |
|---------|----------|
| Датчик | заранее заведён в справочнике (`/admin/structure`), активен, тип совпадает |
| Время | `measuredAt` в UTC (ISO-8601 с `Z`) — время измерения, не отправки |
| Частота | 1 раз в минуту на датчик; пачка — до 500 показаний |
| Ответ | `200 {"saved": N}`; `400` — тип не совпал или датчик выключен; `404` — неизвестный код; вся пачка отклоняется целиком |
| Повторы | шлюз хранит неотправленные показания и досылает их при восстановлении связи; повтор одной точки перезаписывает её в InfluxDB (ключ — датчик + время) |

Единицы: температура `C`, влажность `%`, CO2 `ppm`, аммиак `ppm`, освещённость `lux`, вода `l` (накопительный счётчик или расход за интервал — указывается в названии датчика), корм `kg`.

## 2. Телеметрия по MQTT (S4-06, работает)

Шлюз публикует в брокер (Mosquitto в составе поставки), адаптер пересылает в HTTP API.

| Параметр | Значение |
|----------|----------|
| Топик | `broiler/<site>/<house>/<sensorCode>`, например `broiler/FARM-1/1-04/TEMP-HOUSE-4-01` |
| QoS | 1 (как минимум один раз) |
| Полезная нагрузка | `{"type":"TEMPERATURE","value":26.4,"unit":"C","measuredAt":"2026-10-20T08:15:00Z"}`; допускается просто число — тогда тип и единица берутся из справочника, время — момент приёма |
| Авторизация | логин/пароль брокера на шлюз, TLS на 8883 при работе через интернет |
| Буферизация | адаптер собирает показания до 5 с или 200 штук и отправляет одной пачкой |

## 3. Учёт из учётных систем (S4-07, работает)

CSV в кодировке UTF-8 (или Windows-1251 из 1С), разделитель `;`, десятичный разделитель `,` или `.`. Загрузка — экран партии → «Импорт», или `POST /api/v1/flocks/{id}/import` (multipart, поле `file`).

```
date;mortality;culled;feed_kg;water_l;weight_g;sample_heads;comment
21.10.2026;12;3;1450,5;2610;;;
22.10.2026;10;2;1530;2750;198;100;взвешивание в зоне 2
```

| Колонка | Обяз. | Описание |
|---------|:----:|----------|
| `date` | да | `ДД.ММ.ГГГГ` или `ГГГГ-ММ-ДД` |
| `mortality`, `culled` | да | голов за сутки |
| `feed_kg`, `water_l` | | расход за сутки |
| `weight_g`, `sample_heads` | | если заполнены — создаётся взвешивание |
| `comment` | | |

Строка за дату, которая уже есть, **обновляет** запись (правка попадает в журнал действий). Ответ — число созданных, обновлённых и отклонённых строк с причинами. Импорт целиком в одной транзакции: при ошибке формата не сохраняется ничего.

Выгрузка из 1С: обработка «Выгрузка учёта птичника в CSV» по шаблону выше (пишет интегратор заказчика; формат согласуется на аудите площадки, S3-10).

## 4. Вопросы для аудита пилотной площадки

1. Какие контроллеры микроклимата стоят и умеют ли они отдавать данные (Modbus TCP, OPC UA, облако производителя).
2. Есть ли на площадке шлюз или промышленный ПК, через который можно публиковать в MQTT.
3. В какой системе ведут учёт падежа и корма, кто может делать выгрузку и как часто.
