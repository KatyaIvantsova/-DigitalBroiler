# S1-14. Тест-план Модуля 1 и регресс-набор по текущему функционалу

Статус: **черновик** (issue #14). Тест-кейсы переносятся в трекер; здесь — план и регресс текущей версии.

## 1. Объект и уровни тестирования

| Уровень | Что | Инструмент | Где запускается |
|---------|-----|------------|-----------------|
| Unit | сервисы backend (KPI, правила, аналитика) | JUnit 5, AssertJ | CI, каждый PR |
| Интеграционные | API + Postgres + InfluxDB | Testcontainers, MockMvc | CI, каждый PR |
| Статические проверки фронта | lint, типы, сборка | ESLint, tsc, next build | CI, каждый PR |
| Ручные функциональные | сценарии по ролям | тест-кейсы в трекере | стенд, конец спринта |
| Приёмочные (UAT) | сценарии DoD модуля | протокол | пилот, S6 |
| Нагрузочные | 10 птичников × 50 датчиков, 1 мин | k6 или Gatling | S6-03 |

## 2. Окружения

- **Локально:** `docker compose up` в `backend/broiler_monitoring` + backend + frontend, профиль `demo` для демо-данных.
- **Стенд:** `deploy.yml` с `SPRING_PROFILES_ACTIVE=demo`.
- **Прод:** без демо-профиля, только смоук после деплоя.

## 3. Критерии

- Вход в тестирование спринта: CI зелёный, задачи спринта влиты.
- Выход: все кейсы приоритета P1 пройдены, нет открытых блокирующих и критичных дефектов.
- Классы дефектов: блокирующий (нельзя работать), критичный (неверные данные, безопасность), значительный, незначительный.
