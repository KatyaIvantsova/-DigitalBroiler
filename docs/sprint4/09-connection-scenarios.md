# S4-09. Сценарии подключения пилотной площадки

Статус: **черновик** (issue #52). Критерий готовности — карта датчиков пилота и план подключения — достигается только после аудита площадки (S3-10): какие контроллеры стоят и что они умеют отдавать, знают люди на месте. Ниже — три сценария, из которых по итогам аудита выбирается один, и шаблон карты датчиков.

## Сценарии

| | A. Контроллеры отдают данные | B. Облако производителя | C. Свои датчики |
|---|---|---|---|
| Когда | контроллер микроклимата с Modbus TCP / OPC UA (Big Dutchman, Fancom, Stienen, Munters и т. п.) | контроллеры уже шлют данные в облако производителя, локального доступа нет | автоматики нет или она закрыта |
| Как | промышленный ПК на площадке опрашивает контроллеры и публикует в MQTT (Node-RED или Telegraf) | серверная интеграция с API облака раз в минуту → `POST /api/v1/telemetry/readings` | беспроводные датчики (LoRaWAN / Wi-Fi) → свой шлюз → MQTT |
| Что нужно | ПК или шлюз в сети цеха, карта регистров контроллера, доступ к сети | договор и ключ API у производителя, описание API | закупка и монтаж датчиков, шлюз, питание |
| Срок | 1–2 недели после аудита | 2–4 недели (зависит от производителя) | 3–6 недель (закупка) |
| Риск | закрытые протоколы, нет документации регистров | лимиты API, задержка данных 5–15 мин | монтаж, покрытие радиосети в цехе |

Во всех сценариях данные попадают в систему одним из двух путей, которые уже работают: HTTP-приём (S1) или MQTT-шлюз (S4-06). Код датчика в сообщении должен совпадать с кодом в справочнике «Птичники и датчики».

## Учёт

| Как ведут учёт на площадке | Что делаем |
|---|---|
| 1С | интегратор заказчика пишет обработку «Выгрузка учёта птичника в CSV» по шаблону [S2-09](../sprint2/09-integration-protocol.md); технолог загружает файл кнопкой «Импорт учёта» раз в сутки |
| Excel | сохранить лист как CSV с разделителем «;» по тому же шаблону |
| Бумажный журнал | оператор вносит учёт за сутки на экране партии (S2-03) |

## План подключения (после выбора сценария)

1. Завести птичники, зоны и датчики пилота в справочнике; выдать коды.
2. Выдать шлюзу ключ HTTP или логин MQTT (`deploy/mosquitto/passwd`).
3. Подключить один птичник, неделю сверять показания системы с показаниями контроллера.
4. Подключить остальные птичники, включить правила.
5. Загрузить учёт текущей партии (импорт) и проверить KPI с технологом.
